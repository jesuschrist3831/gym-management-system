# نمودار توالی — سیستم مدیریت باشگاه ورزشی

## ۱. هدف

این سند ترتیب تعاملات بازیگرها با سیستم را در سناریوهای اصلی نشان می‌دهد. نمودارها بر اساس User Storyهای فعلی تهیه شده‌اند و مستقل از فناوری پیاده‌سازی هستند.

## ۲. سناریو اول: ثبت عضو جدید (US-01)

```mermaid
sequenceDiagram
    actor R as مسئول پذیرش
    participant S as سیستم
    participant DB as پایگاه داده

    R->>S: وارد کردن اطلاعات عضو
    S->>S: بررسی کامل و معتبر بودن اطلاعات

    alt اطلاعات نامعتبر است
        S-->>R: نمایش پیام خطا
    else اطلاعات معتبر است
        S->>DB: بررسی و ذخیره اطلاعات عضو
        DB-->>S: نتیجه ذخیره‌سازی
        S-->>R: نمایش پیام موفقیت و شناسه عضو
    end
```

## ۳. سناریو دوم: تمدید عضویت (US-06)

```mermaid
sequenceDiagram
    actor R as مسئول پذیرش
    participant S as سیستم
    participant DB as پایگاه داده

    R->>S: جست‌وجوی عضو
    S->>DB: درخواست اطلاعات عضو و عضویت‌ها
    DB-->>S: اطلاعات عضو و عضویت‌ها
    S-->>R: نمایش اطلاعات عضویت فعلی

    R->>S: وارد کردن مدت تمدید
    S->>S: بررسی معتبر بودن مدت و تاریخ‌ها

    alt مدت یا تاریخ نامعتبر است
        S-->>R: نمایش پیام خطا
    else اطلاعات معتبر است
        S->>DB: ذخیره اطلاعات تمدید
        DB-->>S: تأیید ذخیره‌سازی
        S-->>R: نمایش تاریخ پایان جدید
    end
```

## ۴. سناریو سوم: مشاهده‌ی وضعیت عضویت‌ها (US-07)

```mermaid
sequenceDiagram
    actor M as مدیر باشگاه
    participant S as سیستم
    participant DB as پایگاه داده

    M->>S: درخواست مشاهده وضعیت عضویت‌ها
    S->>DB: دریافت اطلاعات عضویت‌ها
    DB-->>S: فهرست عضویت‌ها و تاریخ‌ها
    S->>S: تعیین وضعیت بر اساس قواعد مصوب
    S-->>M: نمایش فهرست و وضعیت عضویت‌ها
```

## ۵. خطاهای قابل بررسی

| وضعیت | رفتار مورد انتظار |
|---|---|
| اطلاعات ضروری ناقص است | نمایش خطا و جلوگیری از ذخیره |
| عضو پیدا نمی‌شود | نمایش پیام «عضوی یافت نشد» |
| مدت تمدید معتبر نیست | نمایش خطا و عدم تغییر اطلاعات |
| ذخیره‌سازی با شکست مواجه می‌شود | نمایش پیام مناسب و جلوگیری از اعلام موفقیت |

## ۶. نکات

- این نمودارها توصیف رفتاری سیستم هستند و کد اجرایی محسوب نمی‌شوند.
- جزئیات پایگاه داده و رابط برنامه‌نویسی پس از تأیید معماری فنی تکمیل می‌شوند.
- هر تغییر در User Storyها باید در نمودارهای مرتبط نیز منعکس شود.
